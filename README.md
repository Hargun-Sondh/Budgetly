# Budgetly — Personal Budget Tracker

A responsive personal budget tracker built with HTML, CSS, and vanilla JavaScript. This upgraded version adds an Express API and MongoDB Atlas persistence, so transactions remain saved after refreshing the page.

## Live Demo

https://budgetly-azure.vercel.app/

## Tech Stack

- HTML5 — page structure
- CSS3 — styling and responsive design
- Vanilla JavaScript — application logic and DOM manipulation
- Node.js and Express — backend API
- MongoDB Atlas and Mongoose — persistent transaction storage
- Vercel — deployment and hosting

## What Changed in Budgetly 2.0?

Previously, transactions were held in a JavaScript array in the browser and were lost when the page was refreshed. The upgraded version:

- Sends requests to `/api/transactions`.
- Uses Express to handle API requests.
- Uses Mongoose to communicate with MongoDB Atlas.
- Stores transactions with MongoDB-generated IDs and timestamps.
- Supports adding, listing, deleting individual transactions, and clearing all transactions.

## 1. Install Prerequisites

Install Node.js from https://nodejs.org/.

Verify the installation in a terminal:

```bash
node -v
npm -v
```

## 2. Configure MongoDB Atlas

1. Sign in to https://www.mongodb.com/atlas and create a free cluster.
2. Create a database user. This is separate from your MongoDB website login.
3. In Network Access, configure access for local development.
4. Choose Connect → Drivers → Node.js and copy the connection string.
5. Replace the username and password placeholders. URL-encode special characters in the password if necessary.
6. Use `budgetly` as the database name in the connection string. MongoDB creates the database and collection when the first transaction is inserted.

Avoid allowing access from every IP address unless you understand the security implications.

## 3. Configure Environment Variables

In the project root, copy `.env.example` to a file named `.env` and add your actual MongoDB connection string:

```env
MONGODB_URI=mongodb+srv://dbUser:YOUR_PASSWORD@cluster0.example.mongodb.net/budgetly?retryWrites=true&w=majority
PORT=3000
```

The connection string above is an example only. Replace it with your actual Atlas URI.

Never commit `.env` to GitHub or expose the connection string in frontend JavaScript. The `.gitignore` file excludes `.env`.

## 4. Run Locally

Open a terminal in the project root, where `package.json` is located:

```bash
npm install
npm start
```

Open http://localhost:3000.

Do not open `public/index.html` directly in the browser. The frontend needs the Express server for API requests to work.

To check the API, visit http://localhost:3000/api/health. Then add a transaction, refresh the page, and verify that the transaction remains.

## 5. View Saved Transactions

In MongoDB Atlas, open your cluster and select Browse Collections. The database and `transactions` collection appear after the first transaction is saved.

Each transaction contains fields such as:

- `_id` — generated by MongoDB/Mongoose
- `description` — transaction description
- `amount` — transaction amount
- `type` — income or expense
- `createdAt` and `updatedAt` — timestamps

## 6. Deployment on Vercel

The project includes `api/index.js` and `vercel.json` for Vercel deployment.

1. Push the project to GitHub, keeping `.env` out of the repository.
2. Import or connect the repository in Vercel.
3. In Vercel → Project Settings → Environment Variables, configure `MONGODB_URI` for Production. Add it for Preview if needed.
4. Ensure MongoDB Atlas network access permits connections from the deployment environment, following the current Vercel and Atlas guidance.
5. Deploy and test the health endpoint, adding a test transaction and refreshing the page to verify persistence.

If deployment behavior differs from local development, check the Vercel function logs and routing configuration.
